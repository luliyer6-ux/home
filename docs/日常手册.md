# 日常手册

只讲五件事。其他细节看 [建站与维护指南](LULIY-建站与维护指南.md)。

## 1. 发文

文章写在 **Blog A**（`luliy6/luliy6.github.io`）的 Issue 里，网站每天自动同步，也可以马上触发（见下）。

1. 打开 Blog A → Issues → New issue，写标题和正文（图片可直接拖进编辑框）。
2. 贴标签决定版面：`weekly` 周记、`musings` 随笔、`study` 学习、`ai` AI、`Journal` 短札（不进文章列表）、`Library` 阅读笔记。没有标签就是普通文章。
3. 保存后等 Actions 跑完（约 1–2 分钟），文章出现在 luliy.me。

## 2. 改文

- 直接编辑那个 Issue，保存即可，等 Actions 跑完刷新。
- 改了标签后版面没变：看 Blog A 的 Actions 是否跑过；没有就进 Actions → build Gmeek → Run workflow。
- 不想让它显示：关掉或删掉 Issue。

## 3. 加歌

1. 打开 `luliy.me/manage/` → 左边选「唱片」→「新增」。
2. 填歌名、歌手，用上传按钮选 mp3（20 MB 以内）和封面。
3. 点「儲存」，确认列表后提交。约一分钟后网站上出现。
- 调顺序：用上移／下移，再储存。
- 删除：删歌曲条目会连文件一起删。

## 4. 加作品

1. `luliy.me/manage/` → 「作品」→「新增」，填标题、说明，上传文件或填链接。
2. 储存。作品页里的大型文件（超过 20 MB）不要走管理页，放到 `works/` 后用 Git 推送。
- 照片墙同理，在「照片」里加。

## 5. 出问题怎么回退

先判断问题在哪：

| 现象 | 做法 |
|---|---|
| 刚推送就坏了 | GitHub 仓库 → Commits → 找到那次提交 → Revert，合并。一两分钟后恢复 |
| 想先应急 | Cloudflare → Workers & Pages → home → Deployments → 找上一个正常版本 → Rollback |
| 管理页保存错了 | 同上，Revert 那次提交（提交信息以 `Manage:` 开头） |
| 文章没更新 | 看 Blog A 的 Actions 有没有红；`luliy.me/gh/raw/docs/postList.json` 能不能打开 |
| 浏览器还是旧的 | 强制刷新，或改地址加 `?v=1` 试一下，旧缓存通常一天内更新 |

**回退不会回退数据库**：Drive 的 D1 数据不在这个仓库里，改动前后要单独备份。

每次推送后，仓库页面的 Actions 里「Check site」应是绿色；红了就先不要继续改，回来找我。
